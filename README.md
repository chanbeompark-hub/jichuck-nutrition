# 🥗 NUTRITION GUIDE — 내 식단 칼로리 계산기

회원이 직접 나이 · 키 · 체중 · 활동량을 입력하면
**하루 목표 칼로리와 탄수화물 · 단백질 · 지방의 양**, 그리고 그것을 채우는
**맞춤 식단 3안**까지 자동으로 만들어 주는 공개용 웹사이트입니다.

빌드 도구 없는 정적 사이트입니다. HTML / CSS / JS 파일만 있고,
Cloudflare Workers 정적 호스팅으로 배포합니다.

원본은 `회원_식단_자동설계_통합관리_음식DB_150개확장.xlsx` 이며,
그 파일의 계산 로직(회원설정 · 자동식단설계 · 자동식단3안 · 영양가이드 시트)과
음식 DB 181종을 그대로 웹으로 옮겼습니다.

## 계산 방식

### 1. 기초대사량 (BMR)

인바디 값을 입력하면 그 값을 쓰고, 없으면 **Mifflin-St Jeor 식**으로 추정합니다.

```
남성: 10 × 체중(kg) + 6.25 × 키(cm) − 5 × 나이 + 5
여성: 10 × 체중(kg) + 6.25 × 키(cm) − 5 × 나이 − 161
```

### 2. 총 대사량 (TDEE) = BMR × 활동계수

| 활동 수준 | 계수 | 기준 |
|---|---|---|
| 낮음 | 1.25 | 거의 앉아서 생활 · 운동 없음 |
| 보통 | 1.40 | 주 2~3회 운동 |
| 높음 | 1.55 | 주 4~5회 운동 · 활동적인 직업 |
| 매우높음 | 1.70 | 주 6회 이상 · 육체노동 병행 |

### 3. 목표 칼로리 = TDEE + 조정값

| 목표 | 조정값 | 단백질 기본 | 지방 기본 |
|---|---|---|---|
| 다이어트 | −400 kcal | 1.8 g/kg | 0.8 g/kg |
| 유지 | 0 kcal | 1.6 g/kg | 0.9 g/kg |
| 증량 | +250 kcal | 1.6 g/kg | 1.0 g/kg |

### 4. 탄단지

```
단백질(g) = 체중 × 단백질 기준(g/kg)
지방(g)   = 체중 × 지방 기준(g/kg)
탄수화물(g) = (목표 kcal − 단백질×4 − 지방×9) ÷ 4
```

### 5. 식단 3안 자동 설계

각 PLAN 은 **고정 식품**(양이 정해진 것)과 **축 식품 3개**(탄수화물원 · 단백질원 · 지방원)로
구성되고, 축 식품의 양을 순서대로 풀어 목표 영양소를 채웁니다.

1. 고정 식품이 주는 탄수화물을 빼고, 남은 탄수화물을 **탄수화물원**으로 채운다
2. 거기서 따라온 단백질까지 빼고, 남은 단백질을 **단백질원**으로 채운다
3. 마지막으로 남은 지방을 **지방원**으로 채운다

세 축 식품은 화면에서 음식 DB의 다른 식품으로 바꿀 수 있고, 바꾸는 즉시 다시 계산됩니다.
지방이 많은 단백질원(연어 · 고등어 등)을 고르면 지방이 먼저 채워져 오일이 0g이 되고
총 칼로리가 목표를 넘는데, 이 경우 화면에 경고와 대안이 함께 표시됩니다.

### 6. 안전장치

다음 상황에서는 결과와 함께 경고를 띄웁니다.

- 목표 칼로리가 기초대사량보다 낮을 때
- 남성 1,500 / 여성 1,200 kcal 미만일 때
- 주당 체중 변화가 현재 체중의 1%를 넘을 때
- 목표 기간이 요구하는 속도와 실제 섭취량의 예상 속도가 어긋날 때
- 탄수화물이 단백질보다 적게 계산될 때
- 입력한 인바디 값이 추정식과 20% 이상 차이 날 때

## 회원 기록 (D1)

계산기를 쓰기 전에 **이름 · 연락처 · 개인정보 동의**를 받고, 계산할 때마다
그 회원의 마지막 입력값과 결과를 Cloudflare D1 에 남깁니다.
트레이너는 `/admin.html` 에서 전체 명단을 보고 CSV 로 내려받을 수 있습니다.

### 시작 화면의 두 갈래

| 선택 | 동작 |
|---|---|
| **동의하고 시작하기** | 회원 등록 후 계산할 때마다 결과가 서버에 저장됨 |
| **건너뛰고 바로 쓰기** | 서버와 통신하지 않음. 계산기는 전부 쓸 수 있고 기록만 안 남음 |

건너뛴 사람은 화면 위 회색 띠에 `이름 남기기` 버튼이 뜹니다.
나중에 등록하면 **그때까지 계산한 결과가 함께 전송**되므로 다시 계산할 필요가 없습니다.
선택은 브라우저에 기억되어 다음 방문 때 다시 묻지 않습니다.

### API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/register` | 이름 · 연락처 · 동의 저장, 회원 id 발급 |
| POST | `/api/result` | 마지막 계산 결과 갱신 (`calc_count` 증가) |
| POST | `/api/forget` | 회원 본인이 자기 기록 삭제 |
| GET | `/api/admin/list` | 명단 조회 — `X-Admin-Key` 헤더 필요 |
| GET | `/api/admin/csv` | CSV 내려받기 — `X-Admin-Key` 헤더 필요 |
| DELETE | `/api/admin/row` | 한 건 삭제 — `X-Admin-Key` 헤더 필요 |

회원 한 명당 **행 하나**입니다. 다시 계산해도 행이 늘지 않고 마지막 값으로 덮어씁니다.

### 개인정보 처리

- 시작 화면에 수집 항목 · 목적 · 보관 기간을 표시하고, **동의 체크 없이는 등록되지 않습니다**
- 동의하지 않아도 `건너뛰고 바로 쓰기` 로 계산기를 그대로 쓸 수 있습니다 (이 경우 서버 통신 없음)
- 회원은 언제든 `내 기록 삭제` 버튼으로 자기 데이터를 지울 수 있습니다 (DB에서 실제 삭제)
- 관리자 키는 코드에 없고 Cloudflare secret 으로만 존재합니다
- `admin.html` 은 `robots.txt` 와 `X-Robots-Tag` 로 검색 제외 처리했습니다
- 관리자 키는 `sessionStorage` 에만 있어 탭을 닫으면 사라집니다

## 처음 한 번만 하는 준비

### 1. D1 데이터베이스 만들기

```bash
npx wrangler d1 create nutrition-guide-db
```

출력에 나오는 `database_id` 를 `wrangler.jsonc` 의
`PUT-YOUR-DATABASE-ID-HERE` 자리에 붙여넣습니다.

### 2. 테이블 만들기

```bash
npx wrangler d1 execute nutrition-guide-db --remote --file=./schema.sql
```

### 3. 관리자 키 지정

```bash
npx wrangler secret put ADMIN_KEY
```

물어보면 원하는 비밀번호를 입력합니다. 이 값이 `/admin.html` 의 비밀번호가 됩니다.
**길고 추측하기 어려운 값으로 정하세요.** 이 키 하나로 전 회원 개인정보가 열립니다.

## 배포

```bash
npx wrangler deploy
```

`https://nutrition-guide.<계정>.workers.dev` 로 올라갑니다.
배포 후 `public/robots.txt` · `public/sitemap.xml` · `index.html` 의 `canonical`
주소를 실제 도메인으로 바꿔 주세요.

설정이 맞는지만 확인하려면 (업로드 없이):

```bash
npx wrangler deploy --dry-run
```

## 로컬에서 보기

로컬은 별도의 SQLite 파일을 쓰므로 실서비스 데이터에 영향을 주지 않습니다.

```bash
npx wrangler d1 execute nutrition-guide-db --local --file=./schema.sql
```

`.dev.vars` 파일에 관리자 키를 넣고 (이 파일은 git 에 올라가지 않습니다):

```
ADMIN_KEY=아무거나
```

```bash
npx wrangler dev --port 8789
```

`http://localhost:8789` 로 열립니다.

> JS·CSS 를 고쳤는데 화면이 안 바뀌면 캐시입니다. `Ctrl+Shift+R` 로 강제 새로고침하세요.

## 출처와 면책

영양성분 값은 국가표준식품성분표(<https://www.nics.go.kr/food/>)와
USDA FoodData Central(<https://fdc.nal.usda.gov/>)의 대표값입니다.
품종 · 브랜드 · 수분량 · 조리법에 따라 달라지므로, 포장 식품은 제품 영양표시를 우선합니다.

이 계산기는 통계적 추정식에 기반한 **출발점**을 제시할 뿐입니다.
신장질환 · 당뇨 · 임신 · 수유 · 섭식장애 · 약물치료 중인 경우에는
이 가이드보다 의료진과 영양사의 개별 지도를 우선해야 합니다.
